图上相距很远的两个点，在真实网络中一定疏远吗？

同一张网络可以画成两个紧密分开的社团，也可以把六个节点均匀放在一个圆周上。节点坐标经常由布局算法、随机初始化或人工排布决定，不一定是地理位置、实际互动距离或相似度。屏幕上“离得近”只有在明确给定编码约定时才有数学含义。

先决定每一种视觉变量表达什么

可视化并非先把图画漂亮。需要先列出数据字段，再明确颜色、大小、位置、线型与透明度的语义，否则不同视觉变量容易混淆。以六节点、七边的无向图为例：

不同量纲不应任意混用同一颜色梯度。若一条边有方向，必须通过箭头和清晰的图例说明；如果边带权重，也须说明线宽编码权重还是距离成本。

三种常见布局，各有不同的故事

  1. 手工结构示意。人为把三角形并排，突出单一桥边 C–D。适合讲机制和一张小图的明确拓扑；位置没有优化指标。
  2. 圆周布局。均匀排列节点，便于看到每一个节点且不引入随机初始化；连边较多时容易出现交叉，不能单凭交叉判定群体结构。
  3. 力导向布局。把边的吸引与节点间排斥视为可计算作用，寻找较易阅读的坐标。Fruchterman–Reingold 和 ForceAtlas2 都属于相关布局谱系，但公式与实现不同；NetworkX 的 spring_layout 不应冒称“已经运行了 Gephi ForceAtlas2”。

Fruchterman–Reingold 的经典力模型中，若 d 是画布上的欧氏距离、k 是理想间距，典型吸引力大小与 d²/k 成正比，排斥力大小与 k²/d 成正比。方向、迭代温度、边权和停止条件会影响最终坐标，这里的两个量是机制解释而不是直接执行的力学模拟器。

fa(d)=d2k
fr(d)=k2d

如果 d 接近 0，需要算法数值保护。不同实现的具体能量函数与重力项不一定一样，也不要把二维位置本身当作节点嵌入算法的结果或预测标签。

布局切换只影响显示坐标与图形可读性。所有关于节点度数、连通性、介数与社团划分的计算应基于相同的原始邻接关系；如果用户拖动一个节点，也不能在数据中悄悄新增或移除边。

网络大了以后怎么办？

节点数到数万甚至百万时，一张堆满标签与边的“毛线球”往往不再有分析价值。可以使用子图选择、边聚合、社团汇总、过滤阈值、缩放与多层级展示，但过滤之后应显示筛选条件、隐藏数据占比与结果如何变化。避免把过滤前后的网络指标直接摆在同一坐标轴上声称结构发生了演化。

在视觉可访问性方面，不要单靠红绿区分不同社团；提供颜色以外的标签、形状、线型或文本概述。交互控件须能键盘访问，SVG 要有标题与描述；移动端数学和表格应能局部滚动，不能挤出全页。

代码：布局更换而拓扑不变

运行环境 Python 3.11+、NetworkX 3.3+，安装其常见的 NumPy 依赖。spring_layout 运行种子固定为 7，便于复现，但版本不同仍可能导致坐标数值变化；所以只验证节点和边集合不变量。

import networkx as nx

g = nx.Graph([("A","B"), ("A","C"), ("B","C"),
              ("C","D"), ("D","E"), ("D","F"), ("E","F")])
topology = {frozenset(edge) for edge in g.edges()}
before_degrees = dict(g.degree())

schematic = nx.circular_layout(g)
spring = nx.spring_layout(g, seed=7, iterations=100)
assert set(schematic) == set(spring) == set(g)
assert {frozenset(edge) for edge in g.edges()} == topology
assert dict(g.degree()) == before_degrees
assert g.number_of_nodes() == 6 and g.number_of_edges() == 7
assert dict(g.degree())["C"] == 3
assert dict(g.degree())["D"] == 3
print("layout variants preserve topology:", len(topology), "edges")

上面调用的是 NetworkX 的布局接口，正文 SVG 采用独立绘制的示意坐标，不假装为其精确输出。这种区分防止图的制作方式和算法运行的事实混淆。
